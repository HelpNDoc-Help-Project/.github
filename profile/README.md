# HelpNDoc

> One named HelpNDoc project. Finish the topic. Leave a note the next CHM can read.

## Session Card

| Slice | What you do in HelpNDoc | What remains |
|-------|------------------------|--------------|
| Project | Open HelpNDoc and name today's writer desk | A titled help project |
| Topic | Keep only live topics on the HelpNDoc board | A short topic tree |

## How HelpNDoc Sits

HelpNDoc does not replace the word processor, the screenshot tool, or the CHM viewer you already run. It sits beside them as a named writer desk for one job: which help project is live, which topic tree still matches the CHM output, and what the next person should read before you ship.

A first visit should be one short topic, then the same HelpNDoc writer desk the next day. That is enough to see if the help project holds.

## Traffic Light

| Signal | On the HelpNDoc board | What you do |
|--------|----------------------|-------------|
| Green | Named desk, short live topic list | Continue the same help project |
| Amber | Two books mixed in one topic tree | Split the project before you compile |
| Red | No title, no note, topics untitled | Stop and name the project first |
| Clear | Handoff written, live topics few | Close HelpNDoc and leave the desk |

## Open Order

1. Open the last HelpNDoc writer desk, not a new empty help project.
2. Read the topic tree and the last handoff.
3. Finish one visible CHM output pass inside HelpNDoc.
4. Write what changed, then close with fewer untitled topics than you found.
5. If the tree feels crowded, drop anything that belongs to a different HelpNDoc book.

## Desk Fit

| Who | What HelpNDoc holds |
|-----|--------------------|
| Writer desk | Help project, topic tree, and the CHM you ship |
| Shared PC | One HelpNDoc profile per person |
| Support | A repeatable HelpNDoc layout for the same tree |
| Home docs | Personal topics out of the shipped project |

## After a Week

A week in HelpNDoc is not a larger untitled topic pile. It is the same title, a shorter live topic tree, and a note that still makes sense before the next CHM. Take finished topics off the live set so the next visit starts on the help project that is still open.

## Sign-off

- [ ] The HelpNDoc workspace name is short enough to scan
- [ ] Only live topics sit on the tree
- [ ] A second person can read the project handoff
- [ ] The last HelpNDoc help project still opens after a restart
- [ ] Finished topics are off the live HelpNDoc set

## Field Note

HelpNDoc is easier to trust when the writer desk stays smaller than the mixed help dumps it came from. Name the project, keep the live topic tree, finish one visible CHM pass, and write what changed.
